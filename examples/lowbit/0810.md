有一项**值得通知的实质性新线索**。它还没有直接揭开 Rubin attention 2:4 adaptive compression 的底层指令，但对 **第三代 Transformer Engine 的 NVFP4 数据格式/scale 路线**给出了一个此前没有公开到代码层面的 Rubin 专属信号。

### 发生了什么变化

**NVIDIA TransformerEngine 在 2026 年 8 月 7 日 09:59 UTC 新建了 PR #3325：`Prototype NVFP4 with FP8 UE5M3 block scales`。** 这是本次监控启动之后出现的官方 NVIDIA 代码。PR 当前仍为 **Draft / Proof-of-Concept**，作者明确写明：现在已经支持 UE5M3 scale 的 NVFP4 quantize/dequantize，但 **GEMM 尚未提供**。

更关键的是，它不是一个通用 CUDA datatype 实验，而是被 Transformer Engine **明确锁定到 Rubin**：

```text
compute capability == (10, 7)   # Rubin
CUDA >= 13.4
```

并且 API 注释直接说明 UE5M3 “may be used for NVFP4 scaling factors”。也就是说，**SM107 / Rubin 开始出现独有的 NVFP4 block-scale datatype 路线**。 CUDA 13.4 Developer Preview 本身也明确是面向 Rubin 的 preview，并包含 Rubin 相关的新 PTX/数值格式能力。([NVIDIA Docs][1])

还有一个对我们之前讨论非常重要的约束：TE 新代码明确规定

> `NVFP4 4over6 quantization is incompatible with UE5M3 scales.`

也就是说，**4-over-6 与 Rubin 新增的 UE5M3 scale 路径在当前 TE 设计中是两个不能组合的机制**。

同一个 PR 的底层代码还增加了 `disable_second_level_scale` 机制，即允许将 NVFP4 的全局/第二级 scale 固定为 1，只保留 block scale；而 row-scaled NVFP4 又被明确限制为不能去掉这一级 scale。这个细节很有意思，因为它说明 NVIDIA 当前正在把“**NVFP4 block scale 本身是否足够表达动态范围**”作为独立的硬件/软件设计维度。

### 证据可靠性与来源等级

这部分我给 **A 级来源、B+ 级产品成熟度**。

来源是 NVIDIA 官方 `TransformerEngine` 仓库，而且代码直接针对 `CC 10.7 # Rubin`，因此“**Rubin 将支持 UE5M3 NVFP4 block scale**”这个方向本身置信度很高。

但 PR 仍然是 Draft POC，而且作者明确说 GEMM 还没有，所以**不能据此认定最终 TE3 API、Tensor Core operand 格式或量产实现一定保持现在的接口**。

值得注意的是，这个设计并非凭空出现。ICLR 2026 的论文 *Is Finer Better? The Limits of Microscaling Formats in Large Language Models* 此前已经系统研究过 **FP4 + unsigned E5M3 scale**：论文认为 UE5M3 更大的 scale 动态范围可以在保持类似量化精度的同时，避免传统 NVFP4 的 per-tensor/global scaling 操作，而且硬件改动主要是扩展 exponent 处理，代价较低。([arXiv][2])

因此，现在出现的 Rubin-only TE 实现与这条已有研究路线高度吻合。**这是强证据关联，但 NVIDIA 尚未公开声明“#3325 就是基于该论文”**，所以这一点我仍归为推断。

### 对 Rubin adaptive compression 技术路线的含义

我会把目前的模型进一步拆成**两条基本正交的硬件路径**，而不是把所有东西都归为同一个“adaptive compression”。

第一条是我们一直研究的 **attention activation sparsity / compression path**：

`dense QKᵀ → Tensor Memory → 2:4 compress + metadata → sparse Softmax → sparse MMA × V`

这是 NVIDIA 7 月 21 日官方 Rubin 架构文章已经明确描述的：QK 先是 dense，随后从 Tensor Memory 加载时形成 structured 2:4 compressed representation，同时生成 nonzero 和 metadata，Softmax 直接处理 nonzero，之后与 dense V 做 sparse MMA。([NVIDIA Developer][3])

第二条现在越来越清楚，是 **NVFP4 precision/scaling path**：

`FP4 values + Rubin-specific UE5M3 block scale`

它解决的是“如何更高效地表示一个 FP4 block 的数值范围”，甚至可能把传统 NVFP4 的第二级 global scale 消掉；这和“哪些元素被 2:4 丢弃、如何编码 sparse metadata、Tensor Core 如何跳过对应 K work”不是同一个问题。([arXiv][2])

因此，我会**进一步下调“4-over-6 本身就是 Rubin adaptive compression 核心实现”的可能性**。现在不仅 NVIDIA 官方 attention 描述明确是 **2:4 activation sparsity**，TE 代码又直接告诉我们 **4over6 与 Rubin-only UE5M3 不兼容**。([NVIDIA Developer][3])

比较合理的结构现在更像：

**TE3 = 多种彼此正交的低精度/压缩机制集合**，其中至少包括 NVFP4/UE5M3 scale 编码、attention activation 2:4 compression、sparse MMA，以及已有的其他 NVFP4 量化算法；“adaptive compression”更可能特指**运行时 activation → compressed sparse representation**这一数据流，而不是一种新的 NVFP4 quantization recipe。

### 与此前判断相比，需要怎样修正

核心判断**没有推翻，但可以明显收窄**。

我现在对下面三点的置信度提高了：

* **4-over-6 不应再作为 Rubin adaptive compression 硬件机制的主要候选。** 它更像 TE 中独立的 NVFP4 quantization/error-reduction recipe。
* **Rubin 的 TE3 确实有 Blackwell 没有的数值 metadata/scale 语义。** `UE5M3 + CC10.7 only + CUDA13.4` 是目前非常直接的代码证据。
* **真正值得继续追踪的 2:4 关键仍然是 Tensor Memory compression → metadata → sparse MMA 这一链条**：metadata 的粒度、压缩单元在哪里、是否存在动态 K-issue/K-skip、`mma.ws`/zero-column-mask 与它到底是什么关系，而不是继续从 4/6 scale selection 上寻找 adaptive-compression 本体。NVIDIA 官方公开数据流本身支持这一关注点。([NVIDIA Developer][3])

另外出现了一个次级佐证：8 月 7 日新建的 TE PR #3324 在 row-scaled NVFP4 MoE GroupedLinear 上，目前仍然是**逐 expert 调 dense `general_gemm`，没有 dedicated grouped kernel，而且该 loop 不 CUDA-graph-safe**。这进一步说明普通 row-scaled/per-token NVFP4 软件路径目前和 Rubin 专用 compression datapath 是分开的，不应把两者混在一起。

**本轮没有发现足以改变 sparse datapath 判断的新 PTX、cuBLAS 或 zero-column-mask descriptor 披露。** CUDA 13.4 Preview 目前仍只是笼统说明加入了 Rubin 相关的新/更新 PTX 能力，没有公开把某条 PTX 指令直接命名或定义为 adaptive compression。([NVIDIA Docs][1])

所以这次最值得记下的新信号可以浓缩成一句话：

**Rubin TE3 正在增加一种 Rubin-only 的 UE5M3 NVFP4 block-scale 路线，而且它与 4-over-6 明确分离；这进一步支持“adaptive compression 的核心是 activation 2:4 sparse dataflow，而不是 4/6 quantization”的判断。**
