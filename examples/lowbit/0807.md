## 低比特训练技术简报

检索范围以 2026 年 7 月 31 日至 8 月 7 日为主。本周没有高信号的新低比特训练论文或 4over6 更新；主要进展来自 Transformer Engine 的混合量化数据流，以及若干会直接影响 scale/梯度正确性的实现。

### 1. Transformer Engine 正式支持 Fprop、Dgrad、Wgrad 分别选格式

8 月 4 日，TE 合入 `HybridQuantizer` 与 `CustomRecipe(qfactory=...)`。同一 tensor 可以独立保存 rowwise、columnwise 表示，并为三个 GEMM 指定不同格式和来源。

官方示例 `mxfp8_fwd_nvfp4_bwd_factory` 的实际数据流是：

```text
Fprop: weight.row(MXFP8) × input.row(MXFP8)
Dgrad: weight.col(NVFP4) × dY.row(NVFP4)
Wgrad: input.col(NVFP4) × dY.col(NVFP4)
```

实现细节：

* Wgrad 使用的 `input.col`、`dY.col` 可配置 NVFP4 RHT；示例对梯度启用 stochastic rounding。
* Dgrad 的 weight columnwise NVFP4 可来自 `rowwise_dequantized`：先反量化 Fprop 实际使用的 MXFP8 weight，再量化为 NVFP4。这让 Dgrad 对齐 Fprop 中的有效权重，而不是直接从 BF16 master weight 重新量化。
* `columnwise_source="original"` 仍适合 Wgrad input；文档明确不建议对 gradient 使用 `rowwise_dequantized`。
* 已接入 FSDP/FSDP2、TP/SP、CPU offload、activation recomputation、quantized model init 和 attention 边界。
* 关键位置：`pytorch/custom_recipes/quantizer_factory_zoo.py`、`quantizer_factories.py`、`tensor/hybrid_tensor.py`、`tensor/storage/hybrid_tensor_storage.py`。

这是本周最值得跟进的更新：它第一次把“Fprop 用 MXFP8、反向用 NVFP4”之类的研究 recipe 变成可组合的数据流接口。[官方提交](https://github.com/NVIDIA/TransformerEngine/commit/bce8162f1e278500aaa1fb804118278a7305f35d)

局限：factory zoo 明确只是示例，并非经过广泛验证的官方训练 recipe；提交没有收敛质量、吞吐或额外表示带来的显存数据。

### 2. 修复 MXFP8 UE8M0 极端 scale 的错误展开

8 月 5 日，TE 修正 UE8M0 scale byte 的两个特殊值：

```text
code 0   → 2^-127
code 255 → NaN
```

旧的 `exp2f` 位操作会把它们错误展开为 `+0` 和 `+Inf`。因此，软件反量化可能把 scale byte 为零的整个 `1×32` MXFP8 block 静默清零。

修复位于 `transformer_engine/common/util/ptx.cuh`；新增测试直接植入 scale code 0/255，并验证输出为 `2^-127`/NaN。[官方提交](https://github.com/NVIDIA/TransformerEngine/commit/4ff5fdfed0c1cfdb6006bb3376f2d8a958a4b4bb)

推断：这对新的 hybrid `rowwise_dequantized → requantize` 路径、CPU offload、debug/export 特别重要，因为它们会显式展开 MXFP8 表示。提交没有统计真实训练中 code 0/255 的出现频率，也没有说明原生 Tensor Core GEMM 是否曾受影响。

### 3. Model Optimizer 发布 NVFP4 Offline-KD QAD 完整流水线

8 月 5 日新增 Nemotron-3-Nano-30B-A3B 的五阶段示例：

```text
BF16 → NVFP4 PTQ
     → BF16 teacher 缓存 top-K logits
     → NVFP4 student QAD
     → HF export
     → TensorRT-LLM MMLU
```

关键配置位于：

`tools/launcher/examples/nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B-NVFP4/offline_kd_qad.yaml`

实现参数包括：

* calibration：512 samples、最大长度 8192；
* teacher/student：长度 32768、2048 个训练样本、global batch 8；
* `--logits-save-top-k 16` / `--logits-load-dir`；
* student：4×4 GPU、TP2/CP8/EP4，学习率 `5e-5 → 5e-6`。

最重要的工程警告：PTQ、QAD 和 export 三阶段必须一致使用 `--export-default-te-spec`。MoE layout 不匹配会静默丢掉约 93k 个 expert `_amax` keys，示例称这会导致未正确 calibration 的 MMLU 约为 25%。Teacher/student 的序列长度、CP、batch 顺序也必须一致，因为缓存 logits 按 iteration、microbatch 和 CP shard 索引。[官方提交](https://github.com/NVIDIA/Model-Optimizer/commit/7afbfbc85ce145d5233bcb8ec38445394dcb3944)

局限：没有公布 KD 相对普通 NVFP4 QAD 的 loss/MMLU 增益，也没有 top-16 logits 的存储与读取开销；目前证明的是可执行流程，而不是效果。

### 4. MXFP8 fused norm 暴露新的精度边界

7 月 31 日新增：

```bash
NVTE_CUDNN_MXFP8_NORM_OUTPUT_IN_INPUT_DTYPE=1
```

在 cuDNN ≥ 9.25 的 fused LayerNorm/RMSNorm→MXFP8 路径中，该选项把量化前的虚拟 norm 输出从 FP32 改为输入 dtype，即 BF16/FP16；最终存储仍为 MXFP8。

这意味着 quantizer 看到的是已经过 BF16/FP16 舍入的中间值，可能改变 block `amax`、scale 选择及临界点附近的 FP8 code。实现位于 `common/normalization/common.cpp/.h`，目前仅适用于一维 MXFP8 block scaling。[官方提交](https://github.com/NVIDIA/TransformerEngine/commit/40cd2a3f2e924e56d5ba9607393208498c9b8583)

局限：默认关闭，启用时会警告；没有训练精度或 kernel 性能对比。因此只能确认数据流改变，不能推断它一定更快或数值等价。

### 5. Scaled SwiGLU/SReLU 补齐 quantized grouped-MoE 接口

8 月 6 日，TE 增加 `scaled_swiglu`、`scaled_clamped_swiglu`、`scaled_srelu` 及其 backward op。每行 activation 可接收独立 `act_scale`，forward 支持随后输出量化，backward 可同时返回 input gradient 和 scale gradient。

同时：

* NVFP4-RHT grouped MLP 的 SwiGLU interleave 扩展到 size 32；
* grouped quantization 的 input/output offsets 改为批量生成并在前后向复用；
* 减少重复 host offset 计算和临时 allocation。

关键位置包括 `pytorch/ops/_common.py`、fused grouped-MLP 路径及新增 C++/PyBind activation bindings。[官方提交](https://github.com/NVIDIA/TransformerEngine/commit/46e0edf9fd525dd0e89a4f9fbd96d45c9895ba06)

局限：提交没有 profiler 或端到端 MoE step-time 数据；接口支持 optional quantizer，但仍应通过 trace 确认目标配置是否真正减少了独立 quantization kernel。

## Worth testing

* 用 `mxfp8_fwd_nvfp4_bwd_factory` 跑单层 Linear，dump 每个 GEMM 的 row/column dtype、scale shape 与 `columnwise_source`；比较 Dgrad 使用 `original` 和 `rowwise_dequantized` 时的 bias、cosine similarity。
* 在 hybrid、CPU-offload 路径注入 UE8M0 code 0/255，确认 tiny block 不再静默归零且 NaN 能传播。
* Offline-KD 长跑前先审计三个 checkpoint 阶段的 `_amax` key 数量，并用完全相同的 2048 samples 对比 KD 与非 KD QAD。
* 对 MXFP8 norm 环境变量做 A/B：统计 block-scale 翻转比例、量化 MSE、kernel 数和 step time。
* 用 profiler 验证 scaled SwiGLU/SReLU 路径的 activation、quantization kernel 数及 offset allocation；同时对照 unfused reference 检查 scale gradient 和 Wgrad。
